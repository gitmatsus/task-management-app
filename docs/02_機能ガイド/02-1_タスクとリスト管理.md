# 02-1 タスクとリスト管理

## データモデル

### タスク（`todos` 配列）

```javascript
{
  id: string,           // crypto.randomUUID()
  text: string,         // 本文（改行可）
  completed: boolean,
  createdAt: number,    // Date.now()
  listId: string,       // 所属リストID
  dueDate?: string,     // 'YYYY-MM-DD'
  startDate?: string,   // 'YYYY-MM-DD' 開始日（メイン・サブ両方で使用）
  folderPath?: string,  // フォルダパス or URL
  linkType?: string,    // 'folder' | 'url'
  detail?: string,      // 詳細・メモ（複数行可）
  parentId?: string,    // ◀ 値があればサブタスク。親はメインのみ（2階層固定）
  completedAt?: number, // チェックON時に Date.now() を自動セット／OFFで undefined
  // 内部用（エクスポートからは除外）
  _trashedWithParent?: string, // 親と一緒にゴミ箱化されたサブの目印
}
```

### メイン／サブの2階層構造

- `parentId` が未設定 → メインタスク
- `parentId` がメインタスクのIDを指す → そのメインのサブタスク
- **サブのサブは作成不可**（2階層固定）
- ヘルパー: `subTodosOf(parentId)` / `hasSubs(id)` / `isSubTask(t)` / `getParent(t)`（[TList.html:1025-1028](../../TList.html)）

### 完了・削除の親子振る舞い

| 操作 | 親子の動き |
|---|---|
| 完了チェック | **独立**（メイン⇔サブで連動しない） |
| 完了時刻記録 | チェックON時に `completedAt = Date.now()`、OFFで `undefined`（[TList.html:1603-1604](../../TList.html)） |
| メイン削除（ゴミ箱化） | サブも一緒に追従。サブ側に `_trashedWithParent = 親ID` の印を付けて `trash` へ |
| ゴミ箱から復元 | メイン復元時、`_trashedWithParent` が一致するサブをまとめて復元 |
| 完全削除 | メインの完全削除時、ペアになったサブも `trash` から除去 |
| リスト間移動 | メイン移動時、サブもまとめて新リストへ。移動先がメモリストならサブの `parentId` を解除（メモにサブは存在しない） |
| メモリストへの移動 | メイン・サブ問わず `completed` を自動解除 |

### 折りたたみ

サブを持つメインの先頭にトグル（`▶`／`▼`）が出ます。状態は **セッション単位** で `collapsedIds: Set<string>` に保持（localStorage には保存しない）。`data-a="toggle-collapse"` で開閉。

### サブの昇格

- デスクトップ: サブをドラッグして別メインの行の上半分にドロップするとメイン化
- モバイル: サブの長押しメニューに「⬆️ メインに昇格」が追加表示（`data-a="promote-to-main"`、[TList.html:1452-1453](../../TList.html)）

詳細なドラッグ仕様は [02-3 ドラッグドロップ操作](02-3_ドラッグドロップ操作.md) を参照。

### リスト（`lists` 配列）

```javascript
{
  id: string,           // crypto.randomUUID()
  name: string,
  createdAt: number,
  type?: string,        // 'memo' のときメモリスト、未指定は通常リスト(todo)
}
```

## タスクCRUD

| 操作 | 操作方法 | 関数 | 結果 |
|---|---|---|---|
| 追加 | 入力欄 + Enter or 「追加」ボタン | `addTodo(form)` | `addToTop` 設定で先頭／末尾に追加 |
| 改行 | Shift+Enter | - | 入力欄内で改行 |
| 編集開始 | タスク本文をダブルクリック | `startEdit(id)` | 本文・期限・リンク・メモを編集 |
| 編集確定 | Enter または「保存」 | `saveEdit()` | 更新→`save()`→`render()` |
| 完了切替 | 左端のチェックボックス | `toggleTodo(id)` | `completed` を反転 |
| 削除 | ゴミ箱ボタン or ゴミ箱へドラッグ | - | `trash` 配列へ移動 |

`autoSort` が ON のとき、追加・編集の都度 `sortTodos()` で期限日順にソートされます。

## 複数リスト管理

- サイドバーに `lists` を全件表示。`selectedListId` で現在のリストを切替。
- 5件超は折りたたみ（`LIST_COLLAPSE_LIMIT = 5`）。**選択中のリストは常に表示**。
- リスト名のダブルクリックで名前変更。
- 「＋リストを追加」で新規作成。
- リスト削除時は `listTrash` に退避（タスクごと退避）。リスト復元で同時に元のタスクも復元。

### リストタイプ（todo / memo）

`list.type === 'memo'` の場合、UI が変化します。

| 要素 | 通常リスト | メモリスト |
|---|---|---|
| 入力プレースホルダ | 「新しいタスクを入力...」 | 「新しいメモを入力...」 |
| アイコン | クリップ (`I.clip`) | ノート (`I.notepad`) |
| フィルター | 表示（すべて/未完了/完了） | 非表示 |
| 件数表示 | `残り N 件` | `N 件` |
| 自動整列／先頭追加 | 利用可 | フィルター・並び替え機能を簡略化 |

メモリストへタスクを移動した場合、移動時に `completed` チェックは自動解除されます（コミット `bbdc065`）。

## ステータスドット

`listStats(lid)` がリストごとに以下のカテゴリ別件数を返します（[TList.html:980](../../TList.html)）。

| カテゴリ | 条件 |
|---|---|
| `total` | 全件 |
| `active` | 未完了 |
| `done` | 完了 |
| `overdue` | 未完了 ∧ `dueDate < today()` |
| `dueToday` | 未完了 ∧ `dueDate === today()` |
| `future` | 未完了 ∧ `dueDate > today()` |
| `noDate` | 未完了 ∧ `dueDate` 未設定 |

サイドバー右の「ステータス表示」トグル（`toggleListStats`）でドット表示の ON/OFF を切替可能（`todo-app-show-stats`）。

> ステータスドットの集計は **サブも含む全タスク** が対象です（`listStats()` は `parentId` を区別しません）。

## ゴミ箱

| 種類 | 配列 | 永続化キー |
|---|---|---|
| タスクゴミ箱 | `trash` | `todo-app-trash` |
| リストゴミ箱 | `listTrash` | `todo-app-list-trash` |

復元・完全削除はそれぞれのゴミ箱画面から行います。タスクゴミ箱では、ゴミ箱内の項目を「未完了／完了」フィルターへドラッグすることで、その状態として直接復元できます（README.md 記載）。
