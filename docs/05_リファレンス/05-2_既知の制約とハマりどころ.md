# 05-2 既知の制約とハマりどころ

開発・運用中に踏みやすい落とし穴を集約。新しく着手する前に一読を推奨します。

## 日付・時刻

### 深夜0時跨ぎで期限切れ判定がずれる（修正済）

以前は `toISOString().slice(0,10)` でUTC基準の日付文字列を生成していたため、JST深夜0時〜9時の間で「今日」「期限切れ」判定がずれるバグがありました。コミット `9ab45b4` で **ローカル時刻ベース** に修正済み。

```javascript
const ymd = (d) => `${d.getFullYear()}-${String(d.getMonth()+1).padStart(2,'0')}-${String(d.getDate()).padStart(2,'0')}`;
const today    = () => ymd(new Date());
const tomorrow = () => ymd(new Date(Date.now() + 86400000));
```

新しく日付処理を書く際は、必ず `ymd()` / `today()` / `tomorrow()` を使い、`toISOString` を再導入しないこと。

## UI・ポップアップ

### メモポップアップ内のSVGサイズ

ポップアップのラベル内にSVGを入れると意図せず大きく表示される（親要素のflexやサイズ制約が効かない）ことがあります。CSSで明示的に制限してください。

```css
.memo-popup-label svg { width:11px; height:11px; flex-shrink:0; }
```

### メモポップアップの画面外はみ出し

`htmlMemoPopup()` で表示位置を計算するとき、ボタン下のスペースが120px未満なら上に出す、選択方向の利用可能スペースに応じて `max-height` を絞る、画面端でクランプ — のロジックを必ず維持。コミット `3e6cc03` で改善。

### movePopup のタッチ誤作動防止

モバイルで長押し → ポップアップ表示 → 同じタッチイベントが `closeMovePopup` を呼んでしまう問題への対策。ポップアップを開いた直後 **400ms** は閉じる操作を無視します。

```javascript
let movePopupOpenedAt = 0;
function showMovePopup(todoId) {
  movePopupTodoId = todoId;
  movePopupOpenedAt = Date.now();
  render();
}
function closeMovePopup() {
  if (Date.now() - movePopupOpenedAt < 400) return;
  movePopupTodoId = null;
  render();
}
```

### モバイル入力欄のフォントサイズ（iOSズーム）

iOSは `<input>` / `<textarea>` の `font-size` が **16px未満** だとフォーカス時に自動ズームします。モバイル時は16pxを保証してください。

```css
@media (max-width:640px) { .edit-text { font-size:16px; } }
```

### バッジ色の同期

日付バッジ（タスク行右）の色を変更するときは、サイドバーの **件数丸（カラードット）も必ずセットで変更** してください。片方だけ変えると見た目の整合性が崩れます。

## サブタスク（2階層）

### 階層は2階層固定（サブのサブは作れない）

`parentId` が指すのは必ず「メイン（`parentId` 未設定のタスク）」のみ。実装上、ドラッグドロップでサブ化するときの判定に `!targetTodo.parentId` のチェックがあるため、サブをサブ化することは不可能。新規ロジックを追加するときも、`parentId` の連鎖は1段までという前提を崩さないこと。

### サブ有りメインは別メインのサブにできない

ドラッグ判定に `!hasSubs(dragTodoId)` チェックがあり、サブを持つメインを別メインの配下にドロップしても **サブ化されず、通常の並び替えに落ちる**。意図的な挙動（サブのサブ防止のため）。視覚的にも `drop-as-sub` ハイライトは出ない。

### 完了は親子で連動しない

メインを完了にしてもサブの `completed` は変わらず、その逆も同様。「メイン完了＝全サブ完了」のような連動が必要になった場合は明示的な実装追加が必要。

### 削除／復元はペア追従

メイン削除時、サブには `_trashedWithParent = 親ID` の印が付いて `trash` に入る。メイン復元／完全削除のときに同じ印を持つサブをまとめて処理する。サブ単独の削除では `_trashedWithParent` は付かない。

> **`_trashedWithParent` はエクスポートJSONに含めない**（`executeExport()` の `stripInternal()` で除去）。インポート時にも除去される。

### 既存完了タスクには `completedAt` が無い

サブタスク機能導入以前から完了状態だったタスクには `completedAt` プロパティが存在しないため、「✓ MM/DD HH:mm 完了」ラベルは表示されない。新規にチェックOFF→ONし直すと付与される。これは仕様（過去の完了時刻を捏造しない）。

### メモリストでもサブタスクは完全サポート（`9e54034`, `292f859`）

メモリスト（`list.type === 'memo'`）でもサブタスクとして作成・表示・折りたたみが可能です。

### サブ単体を別リストに移動すると `parentId` がクリアされる（`831c546`）

サブタスク単体を別リスト（todo / memo 問わず）に移動すると `parentId = undefined` で **メイン化** されます。元の親が移動元リストに残るため、孤児化を防ぐ仕様。メイン移動時はサブもまとめて追従するので親子関係は保たれます。

### `collapsedIds` / `expandedDoneSubs` は永続化されない

サブ折りたたみ（`collapsedIds`）、完了サブヘッダー展開（`expandedDoneSubs`）はいずれも `Set<string>` のセッション変数で、リロード／アプリ再起動で全リセット。意図的な仕様。同様に `taskFilter` / `showCompletedSection` も非永続。

永続化を追加する場合は localStorage キーを新設（[05-1 localStorageキー一覧](05-1_localStorageキー一覧.md) も併せて更新）。

### ドロップ位置判定の閾値は 0.6（下60%）

`isSubZone = (e.clientY - rect.top) > rect.height * 0.6` で、行の **下60%** がサブ化ゾーン、上40% が並び替え・メイン化ゾーン。閾値を変更する場合、ユーザーの操作感とアクセシビリティ（タッチ環境では下半分の感覚と異なる）を確認すること。

### サブ化対象は親メインの末尾に固定挿入（`9e54034`）

ドラッグでサブ化したタスクは、ターゲット親メインのサブ群の **末尾** に挿入されます。途中挿入は不可（描画が読みづらくなるため）。

## 繰り返しタスク

### `recurrence` と `startDate` は併用不可

繰り返し設定が ON の編集セッションでは、`startDate` 入力欄は隠され、`commitEdit()` で `startDate` を自動クリアします。「繰り返し」と「開始日」のセマンティクスが衝突するため意図的な制約。

### 周期境界リセットは `render()` の冒頭で行う

`applyRecurringResets()` を `render()` 冒頭で呼びます。これにより、ブラウザを開いていなかった間に日付が変わっても、次に画面を開いた瞬間に未完了化＋次回 `dueDate` 更新が走ります。`save()` も内部で呼ばれるため、即座に永続化されます。

### 周期キーの組み立てに注意

`getPeriodKey()` は日次/週次/月次で異なるフォーマットを返します。比較は文字列等価で行い、`isoWeekKey()` の年またぎを誤って文字列比較しないよう注意。

## フィルター／サブ表示

### サブのフィルター判定は親と独立（`a3eab13`）

フィルターチップ適用時、親が条件一致するだけではサブは表示されません。**サブ自身もフィルター条件を満たす必要** があります。「親グループは残すが内容は条件マッチのみ」という挙動。

### 親完了でも未完了サブがあれば active 側に留まる（`a3eab13`）

`splitGroupsByCompletion()` で「親完了 AND 未完了サブが残っている」グループは active 側（未完了一覧）に留まります。完了済みのまま未完了サブを編集できるようにするため。

## ドラッグ＆ドロップ

### Tauri: `dragDropEnabled: false` 必須

`tauri/src-tauri/tauri.conf.json` で **`app.windows[0].dragDropEnabled: false`** を必ず設定。`true`（既定）のままだと Tauri ネイティブD&Dハンドラが先に取ってしまい、ブラウザ側のHTML5 D&D（リスト間移動・ゴミ箱投入）が動きません。

```json
"app": {
  "windows": [{
    "dragDropEnabled": false
  }]
}
```

## ネイティブ環境の癖（Tauri）

### Web 版と Tauri 版で localStorage は非共有

| 環境 | 保存先 |
|---|---|
| Web (ブラウザ) | 各ブラウザの localStorage 領域（ドメイン単位） |
| Tauri | `%APPDATA%\com.tlist.app\EBWebView\` 配下（WebView2） |

データ移行は [02-5 インポートエクスポート](../02_機能ガイド/02-5_インポートエクスポート.md) のJSONで行ってください。

### Tauri: 初回 `npm run dev` は5〜10分

Rustコンパイルで時間がかかります。2回目以降は数秒〜十数秒。

### Tauri: `withGlobalTauri: true`

`window.__TAURI__` をブラウザJSから直接見えるようにする必要があるため、`tauri.conf.json` で必ず `true` に設定。

### Tauri: HTML自動同期

`tauri/package.json` の `predev` / `prebuild` で `TList.html` → `dist/index.html` にコピー。`TList.html` を編集したら `npm run dev` 再起動が必要です。
